# 국내 공공 유동인구·카드매출 데이터의 SaaS 상용 적용성 조사

- 조사 기준일: 2026-09-29 KST
- 목적: RealEstate AI OS 입지분석 데이터 아키텍처 결정
- 범위: 공개 페이지·공식 포털에서 확인 가능한 이용조건, 공간결합, 개인정보·통계비밀, 호출제한, 최신성, 전국 확장성

## 1. 결론

**공공데이터만으로 전국 단위의 일관된 유동인구·카드매출 SaaS를 운영하는 것은 현재 곤란하다.** 서울은 상용 서비스에 넣을 수 있는 공개 API/파일과 공간키가 가장 잘 갖춰져 있지만, 매출은 카드사 결제액 그 자체가 아니라 보정된 **추정매출**, 유동인구도 통신·생활인구를 공간 배분한 **추정 지표**다.[2][3][5]

경기도 공개 데이터도 지역 한정·일회성·출처 설명 부족 또는 모델 추정치라는 제약이 있다.[8][9] 소상공인365는 전국 탐색용 화면·PDF 리포트의 가치가 있지만 공공데이터 등록물 자체가 PDF와 웹서비스 링크이므로, 전국 원천 테이블을 자동 수집하는 계약형 데이터 피드로 볼 수 없다.[10]

따라서 권고안은 다음과 같다.

1. **서울 MVP:** 서울 열린데이터를 `공공 추정지표` 레이어로 도입한다. 화면과 API에서 `실제 매출`·`카드사 총결제액`이라고 부르지 않는다.
2. **전국 제품:** 공공데이터는 상가·행정구역·통계 보조축으로만 사용하고, 전국 유동·결제 지표는 통신사/카드사/데이터 유통사와 별도 상업 계약을 전제로 한다.
3. **출처별 격리:** 공급자·산식·지역·기준시점·라이선스·공간단위가 다른 값을 하나의 `매출액`/`유동인구` 컬럼에 섞지 않는다.
4. **재배포 최소화:** 원본 덤프를 고객에게 제공하지 말고, 허용된 범위에서 출처표시와 함께 파생 지표·시각화로 제공한다. 원자료 다운로드 기능이 필요하면 데이터셋별 재배포 권한을 다시 확인한다.

## 3. 이름에 `카드`가 있어도 무엇을 의미하는가

### 3.1 반드시 분리할 세 종류

1. **카드사 원천 승인/결제액:** 특정 카드사가 관측한 실제 거래액. 다만 그 카드사의 가맹점·회원·승인망 범위이며 곧바로 전체 시장 총매출은 아니다.
2. **표본 카드액:** 1개 또는 일부 카드사 관측액을 그대로 집계한 값. 카드사명·시장점유율·취소/환불·법인/체크/신용 포함범위를 알아야 비교할 수 있다.
3. **추정매출:** 일부 카드 결제액에 보정계수나 확대계수를 적용하여 전체 또는 대상업종 매출을 추정한 값.

서울은 세 번째다. 공식 출처는 카드사 카드결제금액과 보정비율로 추정매출을 만든다고 설명하며, 원천 구성도 BC·KB·SH 카드 자료와 서울시 카드보정·추정매출 단계를 별도로 표시한다.[5] 따라서 UI 문구는 `월 추정매출`, 툴팁은 `일부 카드결제 자료를 보정한 통계 추정치`로 해야 한다.

경기도 `분석 카드매출 행정동 연령`은 이름과 설명만으로 첫째·둘째·셋째 중 어디인지 확정할 수 없다. 공식 메타데이터의 수집방법·시간범위·한계가 비어 있으므로 `실제 카드 총매출`로 표시하면 근거 없는 확대해석이다.[9] 공급기관에서 카드사, 모집단, 표본률, 확대계수, 취소/환불 반영, 온라인·배달·법인·현금 포함범위를 서면으로 확인하기 전에는 제품 KPI로 쓰지 않는다.

## 4. 공공데이터 이용조건·재배포·상업이용

공공데이터포털은 데이터별 공공누리 유형을 확인하도록 하고, 공공누리 1유형은 출처표시를 전제로 상업·비상업 이용과 변형·2차적 저작물 작성을 허용한다고 설명한다.[1]

서울의 세 데이터셋은 모두 1유형이며 각 페이지에서 제3저작권자 없음으로 표시된다.[2][3][4]

그러나 다음을 별도 통제로 둬야 한다.

- **데이터셋 단위 판정:** 포털 전체가 아니라 각 데이터 페이지의 최신 `이용허락범위`, `제3저작권자`, 공지와 약관을 수집 시점마다 저장한다. 공공데이터포털도 제3자 권리가 포함된 경우 권리자의 정당한 이용허락이 필요하다고 명시한다.[1]
- **출처표시:** 서울 검색결과를 노출하는 페이지에는 `서울특별시 공공데이터 사용`을 명시해야 하며, 별도 표시방식이 있으면 따라야 한다.[7]
- **API Key 비공개:** 서울 약관은 인증키를 타인에게 제공·공개·공유할 수 없다고 정한다. 브라우저·고객 SDK에 키를 넣지 말고 서버측 수집기로만 호출한다.[7]
- **재배포:** 공공누리 1유형은 상업적 변형 이용을 허용하지만, 이것만으로 제3자 데이터의 계약범위나 인증키 공유까지 허용되는 것은 아니다.[1][7] 원본 CSV/API 미러를 상품으로 판매하기보다 결과·파생지표를 제공하고, 원본 다운로드 기능은 공급기관에 서면 확인한다.
- **정확성·중단 책임:** 서울 약관은 품질·중단에 대한 책임을 제한하고, 서비스 변경·중단 및 횟수 제한 권한을 둔다.[7] SLA가 필요한 SaaS는 자체 스냅샷·재시도·결측 표시·최종성 검증이 필요하다.

## 5. 좌표·격자·행정동 매칭 리스크

### 확인된 체계

- 서울 상권영역: EPSG:5181, 주민등록 행정기관코드, `상권_코드`·중심 X/Y·행정동코드 제공.[4]
- SGIS: UTM-K, EPSG:5179. 같은 GRS80 계열이라도 EPSG:5181과 동일 좌표로 취급할 수 없다.[11]
- 서울 길단위 유동인구의 내부 산출: 집계구 생활인구를 50×50m 그리드에 배분한 뒤 길·건물로 재배분.[5]
- 서울은 2024년부터 상권분석 공간단위를 표준단위구역으로 바꾸고 공개 시계열을 2021년 이후로 맞췄다.[2][3]
- 행정기관·관할구역 코드는 실제로 시행일별 변경 공지가 계속 나온다.[12]

### 구현 규칙

1. `spatial_unit_id`, `spatial_unit_type`, `geometry_version`, `valid_from`, `valid_to`, `source_epsg`를 필수 컬럼으로 둔다.
2. 서울 지표는 먼저 동일 기준년의 `상권_코드`로 공식 경계에 결합하고, 좌표는 시각화 보조로만 사용한다.
3. WGS84 저장이 필요해도 원본 EPSG와 원본 geometry를 보존하고, 변환본은 파생 컬럼으로 관리한다.
4. 행정동 코드는 문자열로 저장하고 선행 0·코드 유효일을 보존한다. 이름 조인은 금지한다.
5. 행정동/상권/격자 간 값 배분은 단순 centroid join이 아니라 면적가중 또는 건물·도로 가중을 사용하되, 그 결과를 `재추정값`으로 표시한다.
6. 서울 영역 ZIP 수정일(2023-10-23)과 2024년 표준단위 변경 공지가 어긋나므로, 현재 API 상권코드와 내려받은 geometry의 완전조인율을 배포 전 검사하고 불일치면 공급기관 확인 전 차단한다.[2][4]

## 6. 개인식별·통계비밀

공개된 서울·경기 테이블은 개인별 거래나 이동 궤적이 아니라 상권/행정동별 집계값이다.[2][3][9]

그렇다고 결합 후에도 자동으로 개인정보 위험이 사라지는 것은 아니다. 개인정보 포털은 단독으로는 특정인을 알아볼 수 없어도 다른 정보와 쉽게 결합해 알아볼 수 있는 정보와 가명정보를 개인정보 범주로 설명하고, 가명처리 전에 식별 위험성을 검토하도록 안내한다.[13][16]

통계법 제33조는 통계 작성과정에서 알게 된 개인·법인·단체의 비밀을 보호하도록 한다.[14] SGIS가 집계구별 5 미만 값을 서비스에서 제외하는 것도 소지역 통계의 비밀보호가 실제 데이터 제공 제약으로 작동하는 사례다.[11]

제품 통제안:

- 공공 집계값과 고객 CRM·계약·세대·점포 데이터를 결합할 때 개인정보 영향평가 체크를 거친다.
- `성별×연령×업종×시간×요일×소지역` 다차원 교차표를 그대로 외부 노출하지 않는다.
- 셀 건수/인구가 내부 기준 미만이면 suppression, 상위 공간단위 roll-up 또는 범위값으로 대체한다. SGIS의 5 미만 기준은 참고선이지 모든 데이터에 자동 적용되는 법정 단일 기준으로 오해하지 않는다.[11]
- 차분 공격을 막기 위해 인접 기간·필터 조합으로 억제 셀을 역산할 수 없게 한다.
- 개인 또는 특정 소규모 사업자의 매출·동선을 추정·랭킹·타깃팅하지 않는다.
- 카드사·통신사 원천 또는 가명정보를 별도 계약으로 들여오면, 공개 집계데이터와 다른 보안영역·목적·보유기간·결합절차를 적용한다. 개인정보 보호법은 통계작성·과학적 연구·공익적 기록보존 목적의 가명정보 처리를 허용하지만, 이것이 일반 영리 SaaS의 모든 처리 목적을 포괄하는 것은 아니다.[15]

## 7. 호출 제한·운영 안정성

- 서울 Open API는 인증키가 필요하고 1회 최대 1,000건이다. 대량 적재는 페이지 범위를 나눠 호출해야 한다.[6]
- 서울 약관은 별도 이용시간·횟수 지정, 네트워크 과사용·비정상 이용 시 키 정지, 일정 트래픽 이상에서 활용사례 등록 요구, 서비스 변경·중단을 허용한다.[7]
- 경기도 추정매출 API는 개발 자동승인과 달리 운영단계가 심의승인이며, 트래픽 한도는 기관 정책에 따라 달라진다.[8]

권장 수집 구조는 `고객 요청 시 실시간 프록시`가 아니라 `주기적 배치 적재 → 원본 불변 스냅샷 → 정규화/검증 → 서비스 DB`다. API 응답 실패 시 마지막 성공 기준시점을 명확히 표시하고, `source_as_of`, `ingested_at`, `portal_modified_at`을 분리한다.

## 8. 최신성·전국 확장성 판단

서울 공식 출처 페이지의 2026-08-18 업데이트 기준으로 추정매출·생활인구는 2026-06까지이며 분기 주기다. 카드 원천별 기준시점은 BC·KB 2026-03, SH 2026-06으로 서로 다르다.[5] 따라서 “현재 매출”이나 실시간 수요 신호로 쓰면 안 되고 최소 한 분기 이상 후행할 수 있음을 UI에 표시해야 한다.

전국 확장의 핵심 문제는 단순 지역 누락이 아니다. 지역마다 공급자, 카드 모집단, 통신사, 업종분류, 공간단위, 보정모형, 공개주기, 라이선스가 달라 **숫자의 의미 자체가 다르다.** 서울·경기 값을 같은 점수식에 넣으려면 원자료 값을 직접 비교하지 말고 지역 내 percentile/z-score 등으로 표준화한 뒤, 공급자별 calibration과 품질등급을 노출해야 한다.

현재 공식 공개 근거만으로 확인되는 전국 경로는 다음 수준이다.

- 전국 공간·통계 기반: SGIS 경계/격자 — 가능.[11]
- 전국 상권 리포트 탐색: 소상공인365 화면/PDF — 가능하나 자동 공급 피드로 확인되지 않음.[10]
- 전국 동일 산식 유동인구·카드매출 bulk/API: 이번 조사에서 공식 공개 근거를 확인하지 못함.

### 출시 차단 조건

다음 중 하나라도 비어 있으면 핵심 매출·유동 지표로 출시하지 않는다.

- 카드사/통신사 또는 최소한의 원천 범주
- 실제 관측인지 추정인지
- 모집단·표본/보정 방식과 포함·제외 범위
- 기준기간과 갱신주기
- 공간단위·경계 버전·좌표계
- 상업이용·변경·재배포 조건
- 운영 API 승인·트래픽 한도
- 소지역 억제·개인정보 처리 기준

### 최종 Go/No-Go

- **Go:** 서울 MVP의 추정매출·길단위인구·상권영역을 서버측 배치로 적재하고 출처·추정·기준시점을 화면에 명시.
- **Conditional Go:** 경기도 모델 추정매출은 운영심의와 트래픽 한도를 서면 확정한 뒤 보조지표로 추가.
- **No-Go:** 경기도 `카드매출` 일회성 파일을 실제 총매출 KPI로 사용, 소상공인365 화면 스크래핑을 전국 데이터 파이프라인으로 사용, 지역별 숫자를 산식 검증 없이 한 랭킹으로 비교.
- **전국 출시 전 필수:** 민간 공급자와 전국 범위·재판매/파생서비스·SLA·개인정보/가명정보·감사권을 포함한 계약 체결.
