# 주변 상권 카드매출·추정매출·소비 공공데이터 조사

- 조사 기준일: 2026-09-29 KST
- 목적: 매물 좌표 주변 카드매출·상권·소비 분석의 정확도 및 전국 확장성 평가
- 조사 원칙: 공공데이터포털 및 공공기관 운영 사이트의 공개 메타데이터를 우선 사용한다. 실제 카드 매출과 추정 매출, 지역화폐 결제를 구분한다.[1][18]

## 결론

1. **전국 단위에서 좌표 반경으로 바로 조회 가능한 ‘실제 카드매출 OpenAPI’는 확인하지 못했다.** 소상공인시장진흥공단 상가(상권)정보 API는 전국 상가 POI·상권경계·업종·좌표 API이며 매출액은 제공하지 않는다. 반경·사각형·행정동·업종별 점포 조회와 상권경계 조회에는 적합하다.[1]
2. **서울은 조사 대상 중 공간·시간·업종 차원이 가장 촘촘하다.** 상권·상권배후지·행정동·자치구별 추정매출을 분기 단위로 제공하며, 매출금액·건수뿐 아니라 주중/주말, 요일, 시간대, 성별, 연령대까지 포함한다. 2026-07-03부터 상권 공간단위가 표준단위구역으로 바뀌었고 일관성을 위해 2021년 이후 자료만 제공한다.[3][4][5]
3. **전국 확장용 핵심 신규 소스는 한국조폐공사의 지역사랑상품권 업종별 결제 OpenAPI다.**[18] 다수 운영대행사 자료를 통합하고 시군구 5자리·읍면동 8자리 법정동 코드, 업종별 결제금액·건수를 제공한다.[18] 다만 지역화폐 이용분만 나타내므로 전체 카드매출의 대체값이 아니라 보조지표로 써야 한다.[18]
4. **경기는 상권 추정매출 API와 고해상도 카드소비 파일이 모두 있다.** 발달/골목상권의 업종별 분기 추정매출 OpenAPI와 행정동·업종·시간대·성별·연령·요일·매출금액·건수 파일을 함께 사용할 수 있다.[15][8]
5. **제주는 API가 있으나 시계열이 오래됐다.** 제주데이터허브의 내국인 관광객 카드 이용 API는 2016-09~2018-12 월자료이고 일일 1,000쿼터다. 제주관광빅데이터플랫폼의 CSV/시각화는 읍면동·업종·시간대 소비를 제공하지만 공개 OpenAPI는 확인되지 않았다.[30][7][33]
6. **소상공인365 상권분석은 유용한 공식 분석 서비스이지만 데이터 API가 아니다.**[16] 원하는 위치·업종을 선택해 분석하고 PDF로 출력하는 링크형 1회성 자료다.[16] 자동 수집 경로로 간주하면 안 된다.[16]

## RealEstate AI OS 적용 우선순위

### P0 — 바로 통합

1. **소진공 상가(상권)정보 API**: 매물 좌표 기준 반경 내 점포·업종 경쟁밀도와 가장 가까운 상권 ID/경계를 만든다. 매출 데이터가 아니라 **공간 조인 백본**으로 사용한다.[1]
2. **서울 추정매출 3종(상권·배후지·행정동)**: 서울 매물은 `좌표 → 표준단위구역/상권 polygon → 서비스업종 → 최근 4분기`로 조회하고, 행정동 집계로 교차검증한다.[3][4][5]
3. **경기 발달/골목상권 추정매출 API + 경기도 카드소비 파일**: 상권 ID 기반 추정매출과 행정동 카드소비를 이중 소스로 결합한다. 서로 다른 모집단이므로 합산하지 않고 성장률·점유구성·상대지수로 결합한다.[15][8]
4. **한국조폐공사 지역사랑상품권 업종별 결제 API**: 전국에서 공통으로 얻을 수 있는 읍면동·업종 소비 보조지표다. 일반카드 매출과 구분된 `local_currency_amount/count`로 저장한다.[18]

### P1 — 지역별 어댑터

- 부산은 행정동 월별 소비매출, 인천·서울은 지역화폐 업종별 결제를 별도 커넥터로 수집한다.[23][24][25]
- 제주는 제주관광공사 CSV와 제주데이터허브 API를 별도 커넥터로 수집한다.[7][30]
- 서울 소득소비 데이터는 카드매출과 별도 feature family로 저장해 구매력·소비성향을 설명한다. 연 1회 갱신값을 분기 변화로 잘못 해석하지 않는다.[21]
- 소상공인365 분석 PDF는 사용자 요청 시 링크/리포트 보조로 노출하고 서버 배치 수집 대상에서는 제외한다.[16]

### P2/P3 — 검증·벤치마크

- 공정위 가맹업종 평균매출, KOSIS 월간 카드승인, 대전의 과거 카드매출은 공간 추정의 직접 입력보다 전국 경기·업종 평균·백테스트 기준으로 사용한다.[14][34][27]

## 정확도·법적/운영 주의사항

- **관측·추정·지역화폐를 한 지표로 합산 금지**: 서울·경기 ‘추정매출’, 민간 카드사 표본 ‘관측’, 지역사랑상품권 결제는 모집단이 다르다.[3][15][18]
- **카드사 편향**: 경기·부산·제주 데이터는 특정 민간 카드사 또는 구매 데이터일 수 있다. 점유율 보정 여부가 공식 설명에 없으면 `coverage_note=unknown`으로 표시한다.[8][23][7]
- **온라인/본사 결제 누락**: 제주관광공사는 온라인 결제가 본사 사용으로 잡힐 때 누락될 수 있다고 명시한다.[7][33]
- **경계 버전 관리**: 서울은 2024년부터 표준단위구역으로 변경됐다. 과거 상권 코드·polygon을 최신 경계와 단순 연결하지 말고 `geometry_version`을 둔다.[3]
- **비식별 억제값**: 부산 데이터는 개인정보 비식별화를 위해 월 단위로 집계해 제공한다.[23] 다른 소지역 자료도 0을 실제 무매출로 단정하지 않는다.[unverified]
- **라이선스와 재배포**: 소진공 API는 이용허락범위 제한 없음, 서울 추정매출은 공공누리 1유형이지만 민간 원천 카드데이터의 상세 재배포 조건과 데이터별 유의사항은 출시 전 다시 확인한다.[1][3]
- **갱신 모니터링**: 파일형 데이터는 URL이 같아도 기준일·필드가 바뀔 수 있다.[23] ETag/파일 해시, 포털 수정일, 행수, 스키마 diff를 수집 로그에 남긴다.[unverified]

## 미확인·추가 확인 필요

- 한국조폐공사 지역사랑상품권 업종별 결제 API의 실제 운영대행사별 기간·누락률·업종코드 사전 전체 목록은 인증키로 샘플 호출 후 확정해야 한다.[18]
- 경기 카드소비 파일의 카드사명·점유율 보정식·현금 추정 포함 여부는 공개 메타데이터만으로 확정되지 않았다.[8]
- 제주관광빅데이터플랫폼은 공식 CSV 다운로드가 확인되지만 공개 OpenAPI는 확인하지 못했다.[7][33]
- 소상공인365 화면의 매출 분석값을 비공개 내부 API로 우회 수집하는 방식은 공식 OpenAPI로 확인되지 않았으므로 적용 대상에서 제외했다.[16]
